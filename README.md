# UroRock Dashboard

Десктопный «Личный штаб», перенесённый с Apps Script на Vercel. Разделы: Сегодня, Неделя, Календарь, Задачи, Обходы, ИИ‑лаборатория, SMM, Маркетинг. Исходная рабочая компоновка сохранена.

## Как менять дизайн онлайн

Откройте репозиторий GitHub и нажмите `.` — откроется редактор github.dev. Основной интерфейс находится в `src/dashboard.html`. Код опубликован в `Quatermain2/QuaterHub`, кандидат размещён на https://urorock-dashboard.vercel.app. Git-интеграция Vercel пока не подключена: коммиты ещё не публикуются автоматически. После подключения репозитория в настройках Vercel изменения в `main` будут запускать сборку; для проверки используйте отдельную ветку и preview deployment.

## Архитектура

- Статические HTML/CSS/JS на Vercel, серверные маршруты `api/auth.js` и `api/rpc.js`.
- Supabase Auth: отдельный пароль, подтверждённая почта, HttpOnly cookies.
- Отдельный проект Supabase для штаба, независимый от базы приложения «Обеды». Postgres: рабочие данные JSONB, RLS, отдельный список разрешённых пользователей в закрытой схеме, сохранение с проверкой версии.
- `server/desktop-core.js` сохраняет бизнес-логику десктопной версии. `server/adapter.js` работает только с данными Postgres в памяти запроса. К Google API он не обращается.
- Google Calendar → календарь штаба и Notion ↔ задачи — обязательные интеграции. Правила сопоставления и разрешения конфликтов находятся в `server/sync-contract.js`. Подключение и проверка автоматического обмена входят в обязательные условия переключения; до их выполнения релиз является кандидатом.

В репозитории нет рабочих данных, исходных Google ID, паролей и секретных ключей. Publishable key — публичный идентификатор API; доступ к данным ограничен авторизацией и RLS.

## Установка

`npm run build` — сборка; `npm test` — проверка серверной логики.
`schema.sql` создаёт отдельные таблицы штаба, политики и RPC сохранения. Выполнять один раз в целевой базе.
Список разрешённых адресов и исходные рабочие данные вносятся отдельно через административный доступ к базе; они не входят в git или сборку.

При первом входе создайте отдельный пароль и подтвердите почту. Доступ получает только подтверждённый аккаунт, указанный в закрытом списке.

## Конфигурация

`SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` обязательны в переменных среды Vercel и должны принадлежать отдельному проекту штаба. Подключения к другой базе по умолчанию нет; без конфигурации запросы завершаются с понятной ошибкой 503 до обращения к сети. Ключ `service_role` приложению не требуется.
Перед переключением на новую систему проверить импорт, вход, точное сохранение/чтение, конфликт между двумя окнами и все рабочие разделы. Старое развертывание Apps Script сохраняется как резерв до проверки переноса данных.

## Маркетинг

Исходники React лежат в `marketing-src`. Собранный интерфейс — `public/marketing.html`. Для пересборки установите зависимости модуля, выполните `npm run build` в `marketing-src`, затем `node scripts/package-marketing.mjs` из корня. Рабочие проекты загружаются из базы после входа, исходные данные не вшиты в сборку.
